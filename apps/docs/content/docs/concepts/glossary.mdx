---
title: Glossary
description: The words this documentation uses, each for exactly one thing.
---

formdef uses one word per concept, in the code, in error messages and here.

| Term | Meaning |
| --- | --- |
| **form** | A TanStack form instance, with its store. |
| **values** | What the form holds while it runs: `form.state.values`. |
| **data type** | The type of the values: the input type of the schema. |
| **schema** | The [Standard Schema](https://standardschema.dev) that validates a form. |
| **config** | The object `createForm` takes, or the `fields` and `layout` that `Fields` takes. |
| **level** | One object level of a config: its `fields` and its `layout`. |
| **path** | The name of a field while the form runs: `address.zip`, `contacts[0].name`. A key is one segment of it. |
| **field entry** | One entry under `fields`. It has one of four shapes. |
| **leaf, object, array, custom** | The four shapes of a field entry, marked by `widget`, `fields`, `item` and `render`. |
| **item** | One element of an array, and the key of an array entry that describes it. |
| **widget** | A component that takes `FieldOf<V>`, registered under `widgets`. |
| **empty value** | The value a widget holds while nothing is filled in, declared as its static `emptyValue`. |
| **required** | A field whose empty value the schema rejects, so a person has to fill it in. |
| **control** | The element of a widget that a person operates: an input, a button, a list. |
| **form component** | A component registered under `formComponents` and placed by `{ component }` in a layout. |
| **structure slot** | One of `body`, `section`, `row`, `arrayFrame` and `stepper`: the places where formdef renders markup of its own. |
| **array frame** | What renders the items of an array, with their add and remove controls. |
| **layout entry** | One entry of a `layout`: a name, a section, a row, a form component, an inline entry or, at the root, a step. |
| **section, row** | The two layout entries that group others. |
| **inline entry** | A `{ render }` entry in a layout. |
| **step** | A `{ step, label }` entry of a form's root layout: an object of the values, filled in on its own. |
| **stepper** | The structure slot that frames the current step with the progress and the buttons back and next. |
| **complete** | A step that was checked, by its next or a submit of the form, and none of whose fields holds an error. |
| **registry** | What `createRegistry` returns. |
| **shadcn registry** | The distribution of formdef's widgets for shadcn, always named with its qualifier. |
| **base** | The primitive library that shadcn components are built on; for formdef's widgets, Base UI. |
| **validator key** | A key of `validators`: `onChange`, `onBlurAsync` and the others. |
| **error is due** | The moment a widget shows a field's error: the field is invalid, and it was edited and left, the form was submitted, or the step it is shown in was submitted. |
| **form document** | A form described as data: JSON with a format version that holds steps or items, read with `readDocument`. See [Form documents](/documents). |
| **field kind** | What a field of a form document may be: a widget, its value type, its settings, the props they give and its rules. Defined with `defineFieldKind`. |
| **catalog** | Every kind a project offers for form documents, for one registry, collected with `createCatalog`; rendering, checking, validating and describing a document take it. |
| **setting** | A value of a field in a form document that a person may change, such as a unit, declared by its field kind with `setting.*`. |
| **text** | A text of a form document, such as a label: a string for every language, or its translations into the document's `languages`. |
| **item (form document)** | One field, row or section of a form document, under `items`; not an element of an array. |
| **document path** | Where a place sits in a form document, such as `document.steps[0].items[2].visibleWhen`, as problems and errors name it; not the path of a field. |
| **value type** | The kind of answer a field kind gives: one of the built-in `valueTypes`, `text`, `choice`, `choices`, `boolean`, `number`, `decimal` and `date`, or a project's own, defined with `defineValueType` and held by the catalog. |
| **answers** | The values of a form document's fields that show, as the validator returns them and `describeAnswers` describes them. |
| **condition** | When something applies, depending on the values: a `visibleWhen` in a config, a function of the values; in a form document, a comparison of one earlier field, or several combined with `all` or `any`, which decides whether a step, section, row or field shows, whether a field is required, and which case of a setting applies. |
| **rule** | A check of a value: in a config, a validator or a refinement of the schema; in a form document, a fixed check of a field kind on a filled value, built with `rule.*`, which carries a code and the params its error text names. |
| **one call, own shell, plain TanStack** | The three [ways in](/concepts/ways-in). |

Two words keep a second meaning where TanStack owns it: `fields` as the prop of a field group and
as half of a form validator's result, and `mode` as TanStack's field mode next to `validation.mode`.
